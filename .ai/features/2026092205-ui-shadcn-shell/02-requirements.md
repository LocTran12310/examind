# Requirements — shadcn UI, app shell and server-side data tables

## US-01 — shadcn foundation and theme

As a developer I want the components to be exactly shadcn's, and as a user I want light and dark mode.

**Priority:** must

**AC-01** — shadcn only
```gherkin
Given the web source
When I list apps/web/src/components/ui
Then it contains only files generated by the shadcn CLI and no source file imports the old barrel "@/components/ui"
```

**AC-02** — Theme switch
```gherkin
Given any page
When I choose Sáng, Tối or Hệ thống in the header
Then the page re-renders in that theme without reload, the choice persists after refresh, and math and images stay readable
```

## US-02 — App shell

As any user I want a left menu and a header with the organisation and my account on the right.

**Priority:** must

**AC-03** — Sidebar by role
```gherkin
Given I am signed in as a teacher, org admin, super admin or student
When the app renders
Then the left sidebar shows only the groups and items for my role, with icons, the active item highlighted, and it can collapse to icons
```

**AC-04** — Header
```gherkin
Given I am signed in
When I look at the top-right of the header
Then I see the organisation selector with my current organisation, a theme button, and my avatar menu with name, role, "Đổi mật khẩu" and "Đăng xuất"
```

**AC-05** — Mobile
```gherkin
Given a viewport narrower than 768 px
When I open the menu button
Then the sidebar opens as a sheet and closes after navigation
```

## US-03 — Server-side DataTable

As staff I want every list to search, sort and page on the server, with the state in the URL.

**Priority:** must

**AC-06** — Column search row
```gherkin
Given a list with a search row under the headers
When I type in a column filter
Then after 300 ms the URL search params change and the server is asked with that filter; rows are never filtered in the browser
```

**AC-07** — Pagination
```gherkin
Given more rows than the page size
When I use « ‹ › », type a page number or change the page size
Then the URL changes, the server returns that page, and the footer shows "Hiển thị a–b trên T kết quả"
```

**AC-08** — Link restores state
```gherkin
Given a URL with q, column filters, sort, page and page_size
When I open it
Then the first request already carries those parameters and the inputs show them
```

**AC-09** — Selection and toolbar
```gherkin
Given rows with checkboxes
When I select rows
Then Sửa is enabled only for exactly one row, Xóa for one or more after a confirmation dialog, and Nạp reloads the current page
```

**AC-10** — Paged API
```gherkin
Given any list endpoint used by a table
When it is called with q, sort, page, page_size and column filters
Then it returns {items, total, page, page_size} filtered and sorted on the server
```

## US-04 — Screens on the new components

As a user I want every existing screen to work with the new components.

**Priority:** must

**AC-11** — Lists migrated
```gherkin
Given the lists organisations, users, classes, documents, review, question bank, exams, assignments, AI models and tags
When I open each
Then it uses the DataTable (bank keeps its question cards) with its column filters and toolbar
```

**AC-12** — Flows unchanged
```gherkin
Given the upload, review queue, question editor, exam builder, exam runner, results, reports and topic tree
When I use them in light and dark mode
Then they behave as before with shadcn components (dialogs, selects, buttons, toasts)
```
